
# NEVER BUILD ALONE: WORLDFORGE
## Product + Game Design + Technical Blueprint for Claude Code

Version: 0.1
Target: 2027 public launch
Parent ecosystem: Auto AI Technologies / Zayra / Never Build Alone
Primary chain: Sui
Primary deployment: Vercel for web app, account/community/control-plane and web build
Game goal: a social open-world action-adventure where players explore, build, create, cooperate, talk, form communities, and discover the Sui ecosystem without needing to understand crypto first.

---

# 1. NORTH STAR

Never Build Alone: Worldforge should not feel like a "crypto game."

It should feel like a premium social adventure game with:
- Zelda-like freedom of exploration and discovery, without copying Nintendo characters, worlds, systems, art, names, UI, story, or protected assets.
- Fortnite-like social immediacy and live-event energy.
- Minecraft-like creativity and ownership of player-made spaces.
- Roblox-like creator/community extensibility.
- A companion relationship built around Zayra and Chachy.
- Sui technology hidden underneath the experience until ownership, identity, trading, creation, or interoperability makes it useful.

Core promise:

> Explore alone if you want. Build something bigger together. Never Build Alone.

The player should be able to start playing in seconds, meet people naturally, form a crew, build a home/base/community space, complete adventures, create content, earn reputation, collect useful items, and eventually publish their own Sui-powered experiences inside the wider Auto AI platform.

# 2. THE BIG IDEA

Working title:
**Never Build Alone: Worldforge**

Alternate titles:
- Never Build Alone: The Founders
- Never Build Alone: Zayra World
- Never Build Alone: Nexus
- Never Build Alone: Sui Frontier

Recommended title:
**Never Build Alone: Worldforge**

Why:
"Worldforge" communicates exploration + creation + community without sounding like finance or crypto.

Genre:
- Third-person open-world social action-adventure RPG
- Co-op
- Community-building
- Light survival/crafting
- Player housing
- Creator tools
- Sui-powered ownership
- AI companion system
- Live world events

Initial target:
- Web desktop
- Mobile-responsive social/account companion surfaces
- Controller-ready
- Later native PC/mobile build if metrics justify it

Do not try to ship a full AAA open world in v1.
Ship a polished "vertical world" with one city, one wild zone, one social hub, one dungeon/event region, and one creator space.

# 3. WHAT WE ARE BENCHMARKING

## Zelda / modern open-world adventure
Borrow the design principle, not protected content:
- Curiosity drives movement.
- The horizon constantly gives the player a reason to go somewhere.
- Systems interact in surprising ways.
- Exploration itself is rewarding.
- Traversal is fun.
- Puzzles have more than one reasonable solution.
- The player is trusted to experiment.

Worldforge translation:
- Every visible landmark should imply a story, collectible, community, resource, event, puzzle, or creator portal.
- Zayra should suggest possibilities, not give constant instructions.
- Chachy should physically react to secrets, danger, hidden objects, and nearby players.

## Fortnite / UEFN
Benchmark:
- Instant party play.
- Strong identity/cosmetics.
- Live events.
- Easy-to-understand loops.
- Social spaces.
- User-created experiences.
- Frequent reasons to return.

Worldforge translation:
- "Join friend" in one action.
- Crews can enter activities together.
- Seasonal world events.
- Creator portals.
- Public plazas and private crew spaces.
- Spectating, emotes, photo mode, party voice/chat.

## Minecraft
Benchmark:
- Creation becomes identity.
- Player-built worlds produce stories.
- Servers create long-term communities.
- Low rules, high imagination.

Worldforge translation:
- Housing/base construction.
- Community districts.
- Decoration and craft systems.
- Player-created quests and challenge rooms in later phases.
- Persistent crew spaces.

## Roblox
Benchmark:
- One identity can move across many experiences.
- Creators create the long tail of content.
- Social graph is as important as any individual game.

Worldforge translation:
- One Never Build Alone profile.
- One Sui-backed identity layer.
- One friends/crew graph.
- Multiple first-party and third-party Sui games reachable from the world.
- A future Worldforge Creator SDK.

## Rec Room lesson
The social-game idea is powerful, but creation tooling and platform economics must be disciplined.
Do not assume everyone wants to create.
Build an excellent game first.
Give advanced creator tools to the smaller group that proves they want them.

# 4. DIFFERENTIATOR: ZAYRA + CHACHY

## Zayra

Zayra is not a menu chatbot.
She is an in-world AI companion, strategist, guide, builder, and community connector.

Canonical game identity:
- Futuristic Black woman.
- Long locs with violet energy accents.
- Violet glowing eyes.
- Black premium tactical-techwear.
- Purple Auto AI / Never Build Alone visual language.
- Calm, capable, intelligent, never childish.
- Premium cinematic realism.

Zayra can:
- Explain the world.
- Help with quests.
- Help players build.
- Translate game mechanics into simple language.
- Recommend communities or activities.
- Explain Sui concepts only when relevant.
- Help creators design small experiences.
- Generate quest drafts for approved creator tools.
- Suggest squad roles.
- Summarize crew activity.
- Help new players catch up.
- Act as an optional voice companion.

Important:
Zayra should never autoplay the whole game or remove player agency.

## Chachy

Canonical identity:
- Obsidian/chrome cyber-wolf.
- Gunmetal armor plates.
- Violet energy veins.
- Bright violet eyes.
- Strong silhouette.
- Loyal, intelligent, mysterious.

Gameplay functions:
- Detect hidden paths.
- Track targets.
- Warn of danger.
- Mark rare resources.
- Help in combat.
- Revive/support in limited contexts.
- React to strangers/friends/crew members.
- Unlock traversal paths later.
- Become central to the emotional story.

Chachy's behaviors should make players care about him:
- Sleeps near the player's home.
- Greets recurring friends.
- Growls when a suspicious world event begins.
- Finds small gifts.
- Learns cosmetic animation traits.
- Has rare autonomous interactions.

# 6. CORE PLAYER LOOP

Every 10-30 minute session should support this loop:

1. Enter world.
2. See one meaningful event immediately.
3. Choose:
   - Explore
   - Socialize
   - Build
   - Fight
   - Create
   - Play a portal game
4. Earn:
   - XP
   - reputation
   - crafting materials
   - cosmetics
   - collectibles
   - badges
5. Improve:
   - character
   - Chachy
   - home/base
   - crew
6. Discover:
   - new region
   - new player
   - new creator
   - new Sui experience
7. Leave with a reason to return that is not manipulative.

# 7. FIRST 30 MINUTES

Minute 0-2:
- User signs in with a normal account.
- No seed phrase.
- No mandatory token purchase.
- Select simple appearance.
- Zayra appears.
- Chachy emerges from the environment.

Minute 2-7:
- Movement tutorial embedded in escape/exploration sequence.
- Chachy discovers a hidden path.
- Player gets first cosmetic item.

Minute 7-12:
- Arrive at Founders City.
- See real players.
- Optional proximity indicators.
- First simple co-op public event begins nearby.

Minute 12-20:
- Join event.
- Zayra teaches one co-op mechanic.
- Player receives Founder's Mark reputation.

Minute 20-25:
- Player claims starter space/home.
- Places first object.

Minute 25-30:
- Choose one of three paths:
  Explore / Build / Crew.
- Friend/crew suggestion appears only if useful.

Success criterion:
A person who knows nothing about Sui should enjoy the entire first 30 minutes.

# 15. SUI INTEGRATION PRINCIPLE

Rule:
**Use Sui where it makes the game better. Never require blockchain knowledge to have fun.**

Good onchain candidates:
- durable rare cosmetics
- creator ownership records
- achievements that matter across experiences
- limited community artifacts
- creator licenses
- interoperable portal passes
- item provenance
- player-made assets after moderation
- tournament trophies

Keep offchain:
- moment-to-moment movement
- combat frames
- chat
- voice
- temporary matchmaking
- high-frequency game state
- ordinary drops that do not require ownership guarantees

1. **Forge Credits** - offchain soft currency earned through play.
2. **Reputation** - non-transferable.
3. **SUI** - optional ecosystem currency, never required for base gameplay.

- earned through quests/events.

- direct-purchase cosmetics.

- design around token speculation.

# 22. IMPORTANT DEPLOYMENT DECISION

Vercel should host:
- website
- account system
- dashboards
- social surfaces
- creator portal
- game shell
- web client assets
- API endpoints
- lightweight realtime features

Do not assume a serverless web deployment alone is the final architecture for a large authoritative open-world multiplayer simulation.

Plan for a dedicated realtime game-server tier when:
- combat becomes authoritative
- cheating matters
- 20+ players share high-frequency state
- physics must be authoritative
- world shards become persistent

Design the protocol now so the game server can move later without rewriting the entire client.

# 33. VERTICAL SLICE ACCEPTANCE CRITERIA

A stranger can:
1. Open the game URL.
2. Sign in.
